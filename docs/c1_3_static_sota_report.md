## 3. Algorithm Principles

### StaticPairFormer
- **Input embedding**: nucleotide + positional encoding + optional frozen features concatenation
- **Pair initialization**: symmetric outer product + distance + compatibility
- **PairFormer blocks** (12): triangle multiplicative update → triangle attention → outer product mean → pair transition → pair-to-single attention → single row attention → single transition
- **Output head**: symmetric pair logits + unpaired logits + calibration temperature
- **Complexity**: O(L³·P + L²·C) per block; memory O(L²·P + L·C)

### Gradient Checkpointing Fix
- `StaticPairFormer.forward()` wraps each block in `torch.utils.checkpoint.checkpoint(use_reentrant=False)` when `gradient_checkpointing=True`
- `BatchPairFormer` delegates `gradient_checkpointing_enable/disable()` to inner model
- Training engine's `_maybe_enable_grad_checkpoint()` calls `model.gradient_checkpointing_enable()` — now correctly activates

### Fusion Strategies (implemented but NOT integrated into training)
- `SingleOnlyAdapter`: concatenation + projection of single features only
- `PairFeatureAdapter`: concatenation + projection of both single and pair features
- `GatedMultiEncoderFusion`: learned softmax gates over backbones
- `CrossLayerWeightedFusion`: learned weighted sum of intermediate layers
- `TeacherBPPDistillation`: knowledge-distillation loss from frozen teacher

## 9. Failure Matrix and Root Cause Analysis

Per spec: "若未达到：优先判断是数据多样性、backbone、pair trunk、decoder还是长 RNA问题，生成 failure matrix"

### Failure Matrix

| Dimension | Status | Root Cause | Impact |
|-----------|--------|------------|--------|
| **Data diversity** | INSUFFICIENT | Pilot used 10K/228K = 4.4% of training data | Severe underfitting; model sees only 4.4% of families |
| **Backbone** | PARTIAL | RibonanzaNet2 frozen features help (2x), but from-scratch is too weak | Foundation encoder features valuable but not sufficient alone |
| **Pair trunk** | NOT TESTED | Fusion module not integrated; single_only == pair_feature | Cannot evaluate pair-aware fusion strategies |
| **Decoder** | SLOW | nussinov_dp O(L³) bottleneck; 8h per config eval | Limits iteration speed; needs optimization |
| **Long RNA** | NOT TESTED | max_len=400 (config: 512); no long RNA evaluation | Cannot assess long-range structure prediction |
| **Training scale** | INSUFFICIENT | 5 epochs, batch_size=4, 10K samples, 30.9M params | Severe overfitting (train=4.69, val=7.04) |

### Root Cause Analysis

1. **Primary cause — Insufficient training data**: 10K samples is 4.4% of the full 228K dataset. The model (30.9M params) overfits immediately. ViennaRNA uses thermodynamic priors learned from decades of wet-lab data; a neural model needs substantially more training data to compete.

2. **Secondary cause — Fusion not integrated**: The `backbones/fusion/` module has 5 strategies implemented and tested, but `train_c1_3.py` does not use them. Frozen features are always concatenated to `InputEmbedding` regardless of `fusion_type`. This makes `single_only` and `pair_feature` configs identical, wasting half the pilot runs.

3. **Tertiary cause — Training scale**: 5 epochs with batch_size=4 and max_len=400 is far below the config's intended 19 epochs with batch_size=16 and max_len=512. The pilot was constrained by GPU memory (batch_size=4 needed due to OOM at 16) and time.

4. **Evaluation bottleneck**: The `nussinov_dp` decoder runs O(L³) dynamic programming per sample on CPU. With L=400 and 1000 samples, each evaluation takes ~2.5 hours. This limits iteration speed and must be optimized (vectorize, GPU, or skip for pilot).

## 10. Unresolved Issues

1. **Fusion integration gap**: `train_c1_3.py` does not read `fusion.fusion_type` from config. The `backbones/fusion/` module is implemented and tested but not wired into the training script. Fix: add fusion strategy construction in `main()` and pass fused features to model.

2. **Other baselines not run**: EternaFold, MXfold2, UFold, RNAformer, RiNALMo fine-tuned head were not installed/run. These require isolated venvs (per project constraint: "AiZynthFinder / DFT / SOTA 对比工具必须在独立 venv 安装"). ViennaRNA and eFold are the two completed baselines.

3. **OOM at config batch_size=16**: The config specifies batch_size=16 but OOM occurs even with gradient checkpointing at max_len=512. Pilot used batch_size=4 and max_len=400. Full-scale training needs DDP across multiple GPUs or FSDP.

4. **Evaluation speed**: nussinov_dp decoder is prohibitively slow for pilot iteration. Needs GPU implementation or removal from pilot evaluation.

5. **Full-scale training not attempted**: The pilot validates code correctness but does not attempt full-scale training (228K samples, 19 epochs, multiple GPUs). This is the critical next step.
